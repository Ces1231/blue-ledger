Tech Stack
Glide + Google Sheets + Make.com
Tools and what each one does
G
Glide — the app
glideapps.com · Free tier handles everything through Week 12. Builds the mobile-first UI, handles QR scanner, manages user roles, and renders all screens. No code required. If the chapter grows beyond ~500 members or needs advanced automation, upgrade to Glide Maker ($49/mo) — but that's a problem for Year 2.
S
Google Sheets — the database
sheets.google.com · Free. The Master Sheet you already have is the entire backend. All 8 tabs are live. Glide reads and writes to it in real time. Brothers' XP, service hours, and profile data all live here — no server needed.
M
Make.com — the automation
make.com · Free tier (1,000 operations/mo) handles all automations: XP updates, badge awards, profile completion rewards, PIA export. 5 scenarios total. Build them in Weeks 5 and 10. If you exceed the free tier (unlikely before 50+ active members), the Core plan is $9/mo.
C
Cloudinary — avatar hosting
cloudinary.com · Free tier (25GB). Upload the 5 avatar PNGs once. Copy the permanent direct URLs into Glide's If-Then-Else column formula. You never touch it again — images just work.
Z
Zelle / PayPal.me — dues payments
No new account needed. The "Pay Dues" button in Glide is just a URL link to your chapter's existing Zelle or PayPal. Admin marks payment confirmed in the sheet manually. Week 5 setup takes 10 minutes.

Week 5 — Glide build steps
~90 min
1
Add dues columns to Users tab
Open Master Sheet → 👥 Users tab → add 3 columns: Dues Status (text: Paid / Late / Outstanding), Dues Paid Date (date), Amount Owed (number). Fill in values for each member. Sync to Glide.
2
Build Member Dues screen (all roles)
New Screen → Details → 👥 Users (current user row). Add: Dues Status display (large text), Amount Owed field, "Pay Dues" button → Action: Open URL → your chapter Zelle or PayPal.me link. Add "Submit Expense Report" button → Open URL → a Google Form you create for expense submissions.
3
Build Admin Dues view (Admin only)
Admin Panel → add Inline List showing all members. Columns: Name, Dues Status (color-coded chip), Amount Owed. Tap row → edit screen with Dues Status dropdown (Paid / Late / Outstanding) + "Mark Paid" button that sets status to Paid and triggers Make.com to award +50 XP.
4
Create the expense report Google Form
Go to forms.google.com → New Form → fields: Name, Member #, Date, Expense Category, Amount, Description, Receipt Upload. Link form responses to a new tab in the Master Sheet: 💸 Expense Reports. Copy the form URL into the Glide button.
5
Add Chapter Website link to Home screen
Home Dashboard → Add Button component → label: "Chapter Website" → Action: Open URL → your chapter website URL. Place below the quick-action cards.
6
Make.com: Dues paid → +50 XP
Trigger: Row updated in 👥 Users where Dues Status changes to "Paid". Action: Add row to 📋 Engagement Log — Activity: "Dues Paid (On Time)", XP: 50. Action 2: Update Total XP + 50 on that member's row. Add a Dues XP Awarded? flag to prevent double-firing.

WK 8
Avatar & Drip
Unlock logic, PNG display, level progression
~2 hrs
What to build: Upload the 5 avatar PNGs to Cloudinary (or Glide's built-in image storage). In Data Editor → 👥 Users → Add Column → If-Then-Else → Avatar Image URL. Formula: IF XP ≥ 2500 → icon URL, IF XP ≥ 1500 → gold URL, IF XP ≥ 1000 → silver URL, IF XP ≥ 500 → bronze URL, ELSE → base URL. Add same logic for Avatar Level text label. Place Avatar Image URL as the hero image on the Home Dashboard and Digital ID screens. Test by manually bumping a test member's XP past each threshold — watch the avatar change in real time.

Where avatars show: Home Dashboard hero, Digital ID card, Leaderboard rows, Chapter Directory.
WK 9
Leaderboard & Badges
Achievement gallery, full chapter ranking, badge detail views
~2 hrs
What to build: Leaderboard screen — List layout from 👥 Users, sorted by Total XP descending, filter Status = Active. Each row shows avatar image, name, level badge, XP number. Tap → member detail view (read-only profile). Quests & Badges screen — List layout from 🎖️ Quests & Badges tab. Add a computed column "Earned?" that checks if badge name appears in the current user's Earned Badges field. Filter or style the list to show earned badges in green and locked badges in gray. Badge detail view on tap.

Key Glide tips: For the "earned" logic, use a Rollup column counting matches between Earned Badges (text list) and Badge Name — or use a Relations column if your Glide plan supports it. The simplest approach: a computed If-Then-Else checking if the badge name text is contained in the Earned Badges string.

Week 12 · Go-Live 🚀
Full Chapter Launch
🚀 The goal: 85% chapter adoption rate within the first 30 days.
Launch day runbook
1
Seed all member profiles before the meeting
Export your roster. Make sure every active member's Name, Email, Member #, and Induction Year is in the Users tab before they sign in. They fill in professional info themselves — you just seed the core identity fields.
2
Send the Glide app link 48 hours before
Glide generates a shareable URL (and optionally a PWA install link). Send it to the chapter group chat with a message: "We're launching The Blue Ledger at this week's meeting. Sign in before you arrive — use your chapter email."
3
Run a 10-minute demo at the meeting
Project your screen. Show: Home Dashboard → Digital ID (your QR code) → live scan by a Chair → XP appears on the Leaderboard → Quests screen. That's the whole pitch. Let brothers try the scanner in pairs immediately after.
4
Launch the first Quest: "100% Profile Completion"
Announce during the meeting: first 10 brothers to complete their profile earn 100 XP + the Architect badge. Creates immediate engagement momentum. Post the leaderboard in the group chat after the meeting showing who's already ranked.
5
Track adoption at 7, 14, and 30 days
Count Profile Complete? = Yes rows in the Users tab at each milestone. 85% adoption at 30 days = successful launch. If you're below 60% at Day 14, add a dues discount incentive for completion or make it a chapter meeting requirement.
Glide Pro Tips
Things that trip up first-time Glide builders
Save yourself 2 hours of debugging
!
Glide syncs Google Sheets every ~60 seconds on free tier
Don't panic if data doesn't appear instantly. If you need faster testing, use Glide's Data Editor to edit rows directly — changes there are instant. Google Sheets edits take up to 60 seconds to reflect.
!
Row Owners can make your own data disappear
If you turn on Row Owners on the Users table and your test account's email doesn't match any row, the table appears empty. Always test with an account that has a matching email row in the sheet.
!
If-Then-Else chains must be exhaustive
Always end your avatar level formula with a final ELSE clause (Neophyte / base avatar). If the chain has no catch-all, members with 0 XP see an empty image field and the Home Dashboard looks broken on first sign-in.
!
The Barcode Scanner component requires HTTPS
Camera access on mobile requires a secure connection. Glide's published app URL is always HTTPS, so this is automatic. Don't try to test the scanner in Glide's preview mode on desktop — it won't work. Publish the app and test on a real phone.
!
Computed columns don't write to the sheet
Avatar Level, Profile Complete?, QR Data — these are computed in Glide and only exist inside the app. They're invisible in the Google Sheet. That's correct behavior. If you need a value in the sheet (e.g. for Make.com to read), write it explicitly with a Set Column Values action.
!
Test role switching without signing out
In Glide's builder, use the preview user dropdown at the top of the screen to switch between user rows. This lets you see exactly what a Chair sees vs a Member sees without creating separate sign-in sessions. Always verify every new screen in all 4 role contexts before moving on.

Where This Goes After Week 12
Natural evolution path
→
Other chapters want it
When brothers from other chapters see this at a regional conference, they'll ask how to get it. At that point you have two options: (1) share the Master Sheet template and Glide configuration guide as a package other chapters can self-deploy, or (2) turn it into a proper multi-tenant SaaS with the HTML prototype as your developer spec. Either way, the asset you've built is real IP.
→
National org interest
The PIA Builder alone solves a real problem at the national level — chapters struggle to aggregate and report service data. If regional leadership sees your export working cleanly, there's a path to a national pilot. The data architecture is already built for it.
→
Upgrade triggers
Move to Glide Maker ($49/mo) when: you need more than 5 editors, you want a custom domain (bluyledger.com instead of the Glide URL), or your sheet exceeds 500 rows. Move to a custom React/Node app when: you want to charge other chapters for access, you need features Glide can't support (real-time push notifications, complex multi-chapter logic), or you want to own the infrastructure fully.
→
The custom app is already built
The BlueLedger_App.html prototype you have is a pixel-perfect spec for any developer. It has all the screens, the data structures, the UX patterns, and the interaction logic already working. Handing that to a developer cuts their scoping time in half and ensures you get exactly what you designed — not what they assume you wanted.
