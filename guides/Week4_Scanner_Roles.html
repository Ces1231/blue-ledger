Scanner screen — Glide configuration
New Screen → Custom
1
Add Barcode Scanner component
Add Screen → Custom → name: QR Scanner. Add Component → Barcode Scanner. This opens the device camera. Map scanned value to a user-specific column: Scanned QR Value (add this to Users table as a basic text column — it acts as a temporary holding field per user session).
2
Add the Member Lookup computed column
Data Editor → Users → Add Column → Lookup → name: Scanned Member Name. Lookup from: 👥 Users table, where QR Data = Scanned QR Value, return: Full Name. Add a second lookup for Scanned Member # returning the Member # field.
3
Add Activity Type picker
Add Component → Choice → Label: "Activity Type". Options: pull from ⚡ Point Economy tab, Activity / Action column. Map selection to a temp column Selected Activity on Users table.
4
Add XP Lookup from Point Economy
Add Column → Lookup → Selected XP: from ⚡ Point Economy where Activity / Action = Selected Activity, return XP Awarded. This auto-pulls the correct XP value based on what the Chair selects.
5
Configure the Confirm button action
Add Component → Button → "Confirm Check-In". Action chain: (1) Add Row to 📋 Engagement Log — all fields auto-filled from lookup columns. (2) Clear Values — reset Scanned QR Value and Selected Activity. (3) Show Notification → "Checked in! +{XP} XP". (4) Navigate back to scanner camera view.
6
Set scanner tab visibility
Scanner tab → Visibility → Condition: User's Role is Admin OR User's Role is Chair. The tab literally disappears from the nav bar for Member and PIA roles — they never know it exists.
Screen 2 · Confirmation
Scan Confirmation State
After the Chair taps Confirm, a full-screen success state appears for 2–3 seconds before resetting to scanner mode. It shows who was checked in, how much XP was awarded, and confirms the data was written to the sheet.
Confirmation state — implementation
Inline — no new screen needed
💡 Don't create a separate screen for this. Use a Container component with visibility condition: Scanned QR Value is not empty AND confirm action just ran. The container shows the success state; the scanner container hides. After 3 seconds (or on "Scan Next" tap), clear the temp values and the scanner view returns.
1
Add a "Last Scan Success" flag column
Add Last Scan Success boolean column to Users table. Set to True in the confirm action. Set back to False in the "Scan Next" button action. Use this to toggle between scanner view and success view.
2
Success container content
Show: Scanned Member Name, Scanned Member #, Selected XP, check mark icon (Rich Text), timestamp (now). All read from computed columns already set up.
3
"Scan Next Brother" button
Action: Clear Scanned QR Value, clear Selected Activity, set Last Scan Success = False. This resets the screen to scanner mode instantly — the Chair never has to navigate anywhere.

Week 4 Glide Build Steps
Complete in this order — ~4 hours total
Weeks 4–5
1
Assign roles to existing members (15 min)
Open 👥 Users tab in Google Sheets. Fill the Role column for each member: Admin, Chair, PIA, or Member. Save. Glide picks up role changes within ~60 seconds via the sheet sync.
2
Create Glide Roles and map them (20 min)
Settings → Roles → Create 4 roles. For each: Condition → Role column equals "Admin" (repeat for each). Test by signing in as a Chair-role member — the Scanner tab should appear. Sign in as Member — Scanner tab should be invisible.
3
Add temp columns to Users table (10 min)
Add 4 columns: Scanned QR Value (text), Selected Activity (text), Selected XP (number, computed via lookup), Last Scan Success (boolean). These are session-state holders — they reset after each scan.
4
Build the QR Scanner screen (60 min)
New Screen → Custom → source: 👥 Users (current user row). Add: Barcode Scanner component, Activity Type choice picker, Scanned Member Name display (from lookup), Confirm button with full action chain. See Scanner Logic section below for exact action setup.
5
Add scanner tab to nav bar (5 min)
Layout → Nav Bar → Add Tab → QR Scanner screen → icon: camera or QR code. Set visibility: Role = Chair OR Admin. Drag tab to position 4 (between Quests and Profile).
6
Build Role Manager in Admin Panel (30 min)
Admin Panel screen → Add Component → Inline List → source: 👥 Users, all rows, no filter. Each row links to an Edit screen. Edit screen shows the Role field as a Choice component with 4 options. Submit updates the Role column directly in the sheet.
7
Set all screen visibility conditions (45 min)
Work through every screen in the app and apply visibility rules from the Role Matrix above. The most critical ones: Financials (Admin only), Scanner (Chair + Admin), PIA Builder (PIA + Admin), Role Manager (Admin only). Test each by switching your test account's role.
8
Build Financials screen — Week 5 preview (30 min)
New Screen → Details → 👥 Users. Add: Dues Status display, Amount Owed, Pay Dues button (link to Zelle/PayPal URL), Submit Expense Report button (link to Google Form). Admin sub-view: Inline List of all members showing dues status with color-coded chips.
Scanner Deep-Dive
Confirm Button — Full Action Chain
The Confirm Check-In button is the most complex action in the app. It runs 5 steps in sequence. Set each up in Glide's Action Editor in this exact order.
Action chain — Confirm Check-In button
5 sequential actions
1
Add Row → 📋 Engagement Log
Log ID: Template: LOG-{ROWID}
Date: Current date/time
Member #: Scanned Member # (lookup column)
Member Name: Scanned Member Name (lookup column)
Activity Type: Selected Activity
XP Awarded: Selected XP (lookup column)
Logged By: Current user's Member #
2
Set Column Values → Users (scanned member's row)
Find the scanned member's row (where Member # = Scanned Member #). Add Selected XP to their Total XP column. This is the live XP increment — the leaderboard updates immediately.
3
Set Column Values → Users (current user — Chair)
Set Last Scan Success = true. This triggers the success state container to appear on the scanner screen. Also increment the Chair's own session counter: Session Scan Count + 1 (for the "12 / 28" display).
4
Show Notification
Message: {Scanned Member Name} checked in — +{Selected XP} XP. Duration: 3 seconds. This also appears as a toast on Android/iOS system level.
5
Clear Values (on "Scan Next" tap — separate button)
Set Scanned QR Value = empty, Selected Activity = empty, Last Scan Success = false. The scanner camera view reappears automatically because its visibility condition checks that Last Scan Success = false.
⚠️ Steps 1 and 2 must run in order — the row must be added to the Engagement Log before Make.com picks it up for the XP update automation. If they run simultaneously, Make.com may process an incomplete row.
Automation
Make.com — Scanner XP Flow
Scenario: New Engagement Log Row → XP Update
Runs every 15 min or instant webhook
💡 Glide's Set Column Values action (Step 2 above) can handle XP increments directly — you may not need Make.com for the basic scanner flow. Use Make.com for the badge-checking logic that runs after each XP update.
T
Trigger: Google Sheets — Watch for new rows in 📋 Engagement Log
Set to run every 15 minutes (free tier) or use a Glide webhook trigger (paid) for instant processing.
1
Router: Check all badge thresholds
For the member in the new row, pull their updated Total XP from the Users tab. Run through each badge threshold: 25hr service, 50hr service, 100hr service, 10 meetings on time, 3 semesters dues paid, etc.
2
Conditional: If threshold crossed AND badge not yet earned
Check the member's Earned Badges field. If the badge name is NOT already in that field, proceed. If it is, skip — prevents duplicate awards.
3
Action: Append badge to Earned Badges field
Google Sheets → Update Row → Earned Badges = current value + ", BadgeName". Make.com's text concatenation handles the comma-separated list append.
4
Action: Add XP bonus row to Engagement Log
For badges with XP bonuses (e.g. 25-Hour Builder = +250 XP), write a second row to the Engagement Log: Activity Type = "Badge Award: [Badge Name]", XP = badge bonus amount.
