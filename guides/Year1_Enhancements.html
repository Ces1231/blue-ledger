Make.com — RSVP automation flows
2 scenarios
T
Scenario 1: RSVP deadline reminder
Trigger: Schedule — run daily at 8 AM. Filter: Events where RSVP Deadline = today. For each matching event, look up all members who haven't RSVP'd yet (no response in RSVP Responses for this Event ID). Send Gmail reminder to each: 'Don't forget to RSVP for [Event Name] tonight — tap here to confirm.'
T
Scenario 2: Post-event no-show flag
Trigger: Schedule — run at midnight daily. Filter: Events where Date = yesterday AND Active? = Yes. For each RSVP Response where Status = 'Yes' AND Attended? = No → set No-Show? = 'Yes'. Send Gmail to member: 'You RSVP'd for [Event] but we didn't see you — was everything okay?' Set Active? = No on the event.
1
Award RSVP XP
Triggered by webhook from Glide on RSVP submit. Writes +10 XP to Engagement Log. Uses the same XP update flow as the scanner scenario.
✅
RSVP data becomes chapter intelligence over time. After a semester you can see which events have the highest commitment rate, which brothers habitually no-show, and whether RSVP'd brothers attend at a higher rate than walk-ins — all from a simple Google Sheet Rollup.
Enhancement 2 · Month 1 · Quickest Win
Automated Dues Reminder
Make.com sends a personalized email to every member with an unpaid dues balance — 7 days before the deadline, on the deadline, and 3 days after. Zero admin work after setup. This alone typically recovers 15–20% of late dues.

Make.com — 3 automated reminder scenarios
~45 min build total
1
7-Day Reminder
Trigger: Schedule daily 9 AM. Filter: Today = (Dues Deadline from ⚙️ Config tab) - 7 days. Find all Users where Dues Status ≠ 'Paid'. For each: Gmail → To: member email, Subject: 'Reminder: Chapter dues due in 7 days', Body: personalized with member name, amount owed, Zelle link, and current XP loss warning ('Pay on time to earn your +50 XP bonus').
2
Deadline Day Reminder
Trigger: Schedule daily 9 AM. Filter: Today = Dues Deadline from Config. Find all Users where Dues Status ≠ 'Paid'. Gmail → more urgent subject: 'Today is the dues deadline — pay now to avoid a late fee'. Include amount owed and Zelle link. CC to Treasurer.
3
Grace Period Warning
Trigger: Schedule daily 9 AM. Filter: Today = Dues Deadline + 3 days. Find all Users where Dues Status = 'Late'. Gmail → Subject: 'Financial hold in {days} days — urgent'. Body: financial hold consequences (no voting, no officer eligibility). Treasurer CC'd. Forward to President if still unpaid after 7 days.
4
Stop sending when paid
In each scenario: before sending, check if Dues Status has changed to 'Paid' since yesterday. Use a Filter module: only proceed if Dues Status ≠ 'Paid' AND Dues XP Awarded? ≠ 'Yes'. This prevents a paid member from getting a reminder the same day the Admin marks them paid.
Email template — personalized reminder
Copy this into Make.com Gmail module
S
Subject line
'[Action Required] Chapter Dues — {First Name}, {Amount} due by {Deadline}'
S
Email body structure
Greeting with first name → current dues status (Paid/Late/Outstanding) → exact amount owed → Zelle link (clickable) → PayPal link → XP incentive reminder (+50 XP for on-time payment) → what happens if not paid (financial hold consequences) → contact info for questions → chapter signature block
S
Personalization variables (Make.com)
First Name → split Full Name by space, take index [1]. Amount → Amount Owed column. Deadline → Dues Deadline from Config tab. Days remaining → date difference calculation using Make.com math functions.
💡

Nothing. Stripe deposits directly to the chapter bank account. Make.com auto-marks dues paid in the sheet and awards XP. The Treasurer opens the sheet and all payments are already confirmed — no manual matching, no "did you send it?" texts.

Stripe setup — one-time configuration
~1 hour
1
Create Stripe account
Go to stripe.com → create account → complete business verification (use the chapter's EIN or the Treasurer's personal account if no chapter EIN). Stripe requires identity verification before live payments.
2
Create a Payment Link for chapter dues
Stripe Dashboard → Payment Links → Create → Product: 'Chapter Dues — Fall 2025' → Price: $85.00 (or your chapter's dues amount) → collect: customer email (required for Make.com matching). Copy the Payment Link URL.
3
Update the Glide button
Financials screen → 'Pay Dues' button → Action: Open URL → replace old Zelle/PayPal URL with your Stripe Payment Link URL. Members tap → Stripe checkout opens in their browser → returns to app on completion.
4
Add custom fields to Stripe checkout
Payment Link settings → Collect additional information → add: 'Member Number' (text field, required). This is how Make.com knows which sheet row to update — it reads the Member # from the Stripe charge metadata.
5
Set up Stripe webhook in Make.com
Make.com → Create new scenario → Trigger: Stripe → Watch Events → select 'payment_intent.succeeded'. This fires every time a payment clears. Stripe sends all charge details including the customer email and Member Number to Make.com automatically.
6
Make.com action chain on payment success
(1) Extract Member # from Stripe charge metadata. (2) Google Sheets → Update Row in 👥 Users where Member # matches: set Dues Status = 'Paid', Dues Paid Date = today, Amount Owed = 0. (3) Add Row to 📋 Engagement Log: Activity = 'Dues Paid (On Time)', XP = 50. (4) Gmail → send confirmation email to member: 'Payment received — +50 XP awarded. You're all set for the semester.'
⚠️
Stripe charges 2.9% + 30¢ per transaction. On $85 dues that's ~$2.77 per payment. Decide whether the chapter absorbs this (treat it as an admin expense) or adds it to dues ($87.77 rounded). Most chapters absorb it — the time saved on manual confirmation is worth far more than $2.77 per member.
Semester dues update
Every semester — 5 minutes
1
Update the Stripe Payment Link price
Stripe Dashboard → Payment Links → edit the dues link → update price for the new semester. Or create a new link each semester for cleaner reporting.
2
Update Config tab
⚙️ Config → Dues Amount → update to new value → Dues Deadline → update. Make.com reminder scenarios read from here — no other changes needed.
3
Reset Dues Status in Users tab
At the start of each semester: set all members' Dues Status = 'Outstanding' and Dues XP Awarded? = 'No'. A simple Find + Replace in Google Sheets (Ctrl+H) handles this in 30 seconds.

Enhancement 6 · Month 4–6 · Strategic
Multi-Chapter / National Expansion
When other chapters ask for The Blue Ledger (and they will), this is the architecture for scaling. Each chapter gets its own Google Sheet connected to one shared Glide app. A National Admin dashboard aggregates PIA data across all chapters. Built on the same free-tier stack.
🏛️
Chapter-level
Each chapter has its own Master Sheet. Their Glide app connects to their sheet only. Members only see their chapter's data. Completely isolated — one chapter's data never appears in another's app.
1 sheet per chapter
🗺️
Regional level
A Regional Sheet aggregates PIA export data from all chapter sheets. Make.com copies relevant PIA rows into the Regional Sheet on each export. Regional Directors see combined service hours and program impact across all chapters.
1 sheet per district
🌐
National level
One National Dashboard Glide app reads from all Regional Sheets. National officers see total service hours, total members, and chapter-by-chapter engagement scores — without accessing any chapter's individual member data.
1 dashboard total
Deployment kit — share with other chapters
Package once, deploy many
1
Create a Master Sheet template (shared copy)
Make a copy of your Master Sheet with all sample data cleared. Share it as a Google Sheets template (File → Make a copy → distribute link). New chapters duplicate it, fill in their roster, and connect to their own Glide app. Setup time for a new chapter: ~2 hours.
2
Glide app — multi-chapter routing
The simplest approach: each chapter gets their own Glide app connected to their own sheet. All apps use the same template (Settings → Clone App in Glide). No code sharing required — just a new Glide project per chapter. Alternatively, use Glide's Organizations feature (paid tier) for a single app with multiple data sources routed by chapter ID.
3
Chapter ID column
Add Chapter ID to every tab in the Master Sheet (e.g. 'TAU-TAU-SIGMA', 'ALPHA-BETA'). When building the Regional aggregation, Make.com reads this column to know which chapter each row belongs to. This enables cross-chapter comparisons without data co-mingling.
4
Regional PIA aggregation scenario
Each chapter's Make.com 'Export PIA' scenario (from Week 10) gains one extra action: after emailing the district, also append the chapter's PIA rows to the Regional Sheet. The Regional Sheet is a read-only aggregate — no one writes to it directly.
5
National Dashboard Glide app
One Glide app connected to the Regional Sheet. Visible only to National Officers (email allowlist). Shows: total chapters enrolled, combined service hours YTD, top-performing chapters by hours and programs, PIA export status per chapter. Built as a read-only Details screen — no edit permissions.
6
Monetization option (Year 2+)
If other chapters adopt this, you've built real IP. Options: (1) free and open — builds goodwill and national org credibility. (2) $50–100/chapter/semester deployment fee — covers your Make.com Core upgrade + time. (3) Pitch to the national org as an official tool — they fund development, you run it. The HTML prototype in this repo is already your product demo.
Rollout priority — which chapters to approach first
Strategic sequence
1
Graduate chapters in your district first
Grad chapters typically have more stable leadership, better dues collection, and stronger appetite for professional tools. They're also more likely to pay for a turnkey solution.
2
Chapters with active, tech-comfortable leadership
One engaged Vice President can deploy this in a weekend. Target chapters where you know the officers are motivated — one successful peer deployment is worth 10 cold pitches.
3
Regional conference demo
Present at the next regional conference. Live-demo the scanner and leaderboard. Five minutes on stage reaches more potential chapter adopters than months of individual outreach.
4
National org pilot pitch
After 3–5 chapters are live, compile a one-pager: chapters enrolled, total service hours tracked, PIA reports auto-delivered. The data tells the story. Submit to the national office as a pilot program proposal.
💡
The multi-chapter architecture doesn't require any new tools — it's just replication of the same Glide + Sheets stack you already have. The constraint is your time, not technology. Build the deployment kit first (the template + documentation), and let chapter leads deploy themselves with occasional support from you.
